# 实验二记录：简单文本编辑器

## 界面布局与实现

主窗口用 Qt Designer 搭：`mainwindow.ui` 里放 `QMainWindow` + 中央 `QVBoxLayout`（`layoutMargins` 全部设成 0，让编辑区贴着工具栏和状态栏），中间的控件先把类型填成 `QPlainTextEdit`，再通过“提升为”改成自己的 `CodeEditor`。菜单和工具栏全部用 Action 编辑器建 `QAction`，同一个 Action 既挂菜单也挂工具栏，所以两边的文字、快捷键、使能状态天然一致。

工具栏按功能用分隔线分成五组：文件、撤销/恢复、剪贴板、格式、视图。工具栏按钮显示的文字用 Action 的 `iconText` 单独设成短的（比如“新建”），菜单里仍是带助记符的“新建(&N)”，这样按钮不会被 `(N)` 撑宽。

编辑区左侧的行号栏是一个贴在 `QPlainTextEdit` 上的小 `QWidget`，宽度随总行数位数变化，`resizeEvent` 里跟着调整几何位置；滚动时通过 `updateRequest` 信号做局部重绘，只画可见区域的行号。当前行用 `ExtraSelection` 铺一条浅黄色底，颜色按调色板深浅取，深色主题下不会突兀。

查找、替换、关于三个对话框各自有 `.ui` 文件。查找和替换设成非模态（`setModal(false)`），这样窗口开着还能直接点编辑区改内容。

## 关键实现说明

- **文件读写**：保存用 `QSaveFile`，先写临时文件再整体替换，写到一半出错不会把原文件弄坏；读取时先按 UTF-8 解，出现替换字符再退回本地编码（中文 Windows 下是 GBK）。
- **修改状态**：不额外维护 `bool` 标志，直接用 `QTextDocument::isModified()`，接 `modificationChanged` 信号刷新标题，保存、新建、打开后统一走 `setCurrentFile()` 把状态清干净。
- **Action 使能**：撤销/恢复接 `undoAvailable` / `redoAvailable`，剪切/复制接 `copyAvailable`，粘贴接剪贴板 `dataChanged` 后查 `canPaste()`，启动时先把这几个手动置灰。
- **查找**：逻辑写在 `CodeEditor::findNext()` 里，查找和替换两个对话框共用。向下找从选区末尾开始，向上找从选区开头开始；没找到就回到另一端再找一次，用 `wrapped` 参数告诉调用方是否绕回了，绕回时只在对话框里给一行提示，不弹窗，免得连续查找被打断。
- **替换**：只有当前选中的内容确实等于查找词时才替换，否则先跳到下一个匹配，避免误改无关文字；“全部替换”用 `beginEditBlock` 把改动合成一步，撤销时一次就能退回。
- **颜色设置**：`QPlainTextEdit` 没有 `setTextColor()`，用 `QTextCursor::mergeCharFormat()` 把格式合到选区上；没有选区时把光标连同格式交还给编辑区，之后输入的文字才用新颜色。

## 边界与异常场景

| 测试输入 | 修复前可能现象 | 原因分析 | 修改方法 | 修改后结果 |
| --- | --- | --- | --- | --- |
| 修改内容后直接关窗口 | 内容直接丢失 | `closeEvent` 没检查文档修改状态 | 重写 `closeEvent`，先问“是否保存”，选取消则 `ignore()` 事件 | 弹出“保存 / 丢弃 / 取消”，取消后窗口不关 |
| 另存为对话框点取消，随后继续编辑 | 内容被当成已保存，标题上的 `*` 消失 | `saveFile()` 里把“取消”也当成保存成功返回 | `saveFileAs()` 取消时返回 `false`，`maybeSave()` 拿不到成功就不继续后续动作 | 取消另存为后标题仍带 `*`，关闭时还会再提示 |
| 打开含 `\0` 的二进制文件（如 exe 改名成 .txt） | 编辑区塞满乱码，后续保存会把原文件写坏 | 没判断文件是不是文本 | 读入后检查 `\0`，命中就提示“看起来不是文本文件”并中止 | 只弹提示，编辑区内容不变 |
| 选中文字后按 `Ctrl+H`，替换词与选中内容不完全相同 | 把无关内容替换掉 | 没核对当前选区和查找词是否一致 | 替换前用 `QString::compare` 按大小写规则比对，不一致就先跳到下一个匹配 | 只有真正匹配的选中的内容才会被替换 |
| 在最后一个匹配处继续点“查找下一个” | 以为没找到，或者死循环 | 到尾后没有处理回绕 | 第一次找不到时从文档另一端再找一遍，并用 `wrapped` 标记提示 | 回到开头继续查找，对话框显示“已到达文档另一端” |
| 查找目标为空时点“查找下一个” | 可能匹配到空串导致光标原地乱跳 | `QTextDocument::find()` 传空串的行为不确定 | 入口先判空并提示“请先输入要查找的内容” | 只弹提示，不做查找 |
| 打开一个 30 MB 的文本文件 | 界面卡住，像死机 | 一次性读入并排版超大文本 | 打开前判断文件大小，超过 10 MB 直接提示不支持 | 立刻提示，不读文件 |
| 用“全部替换”把 “a” 换成 “aa” | 担心替换后又在原地匹配到自己，陷入死循环 | 替换后查找起点没往后挪 | 每次替换后把游标更新到插入文本之后，再从新位置继续找 | 正常结束，只替换原有匹配 |

## AI 辅助与自己的修改

按实验要求记录一个比较有代表性的过程。

- **问题**：`QPlainTextEdit` 上怎么加行号？直接往上画会被文本盖住，滚动时行号还会错位。
- **提示词**：给 `QPlainTextEdit` 加一个左侧行号栏，要求行号随内容增长自动变宽、滚动跟文本同步、可以整体隐藏。
- **AI 给出的方案**：从 `QPlainTextEdit` 派生新类，内部放一个 `LineNumberArea` 小控件，用 `blockCountChanged` 更新宽度、`updateRequest` 做滚动重绘、`resizeEvent` 调整几何位置，`paintEvent` 里按 `firstVisibleBlock()` 逐行画数字。
- **运行验证**：行号能显示、能跟着滚动，但发现两个问题：① 行号栏底色是写死的浅灰，把系统切到深色主题后编辑区是黑的、行号栏是白的，很难看；② 改了“编辑器背景色”之后行号栏不刷新，只有滚动时才跟着变。
- **自己的修改**：底色改成从 `palette().color(QPalette::Base)` 推出来（深色就压暗、浅色就用浅灰），当前行高亮也按同样规则取色；再重写 `changeEvent`，收到 `PaletteChange` 时让行号栏重绘一次。

## 出错分析与总结

1. 一开始把“查找”逻辑分别写在查找和替换两个对话框里，改一处要改两遍，还出现过两边对“是否回绕”的判断不一致。后来把查找抽到 `CodeEditor::findNext()` 里公用，两个对话框只负责收集条件和显示提示，问题就没了。
2. 颜色设置最开始想直接改 `QTextCursor` 的 `charFormat`，结果没有选中内容时新输入的文字还是黑的。查了 Qt 文档才知道要 `mergeCharFormat` 之后再把光标 `setTextCursor` 交还给编辑区，格式才会作用到后续输入。
3. 关于对话框一开始点了没反应，排查发现是 `actionAbout` 忘了 `connect`，菜单项和工具栏都建好了、槽函数也写了，就是没连上。这件事提醒我：界面配完要逐项点一遍，不能只看界面长得对不对。
4. 用 Qt 6 写 5.12 的例子会遇到少量接口差异（比如 `QTextCodec` 被移除），这次尽量用 `QString::fromUtf8` / `QSaveFile` 这类两代都能用的写法，遇到必须改的地方在 README 里写清楚了。

整体上，AI 在结构设计和 API 用法上给的建议比较有用（行号栏的分工、Action 共用、`QSaveFile` 原子写入），但边界情况的处理基本都是自己跑出来问题再补的：取消另存为被当成保存成功、替换误伤无关选区、全部替换的死循环担心，这些都是实际点着用才发现的。最后按实验要求逐项做了手动验证，并在文档里记了输入和现象。
